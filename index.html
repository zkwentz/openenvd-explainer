The workload cannot read or rewrite the retained collector through its event pipe. It can still lie in the reports it sends. Process events contain a PID and spawn/exit label; they do not contain command lines.
Continuous filesystem, process, and resource sampling requires those observer streams to be configured. Network logging also requires its configured stream. No subscriber is needed for configured collection to occur; durable storage is a separate integration.
How to keep an honest timeline
  • Preserve provenance. Label workload reports, daemon samples, firewall decisions, and grader findings separately.
  • Use run and episode IDs. Native events contain seq, ts, type, and data. Sequence numbers restart at zero after reset; the envelope has no episode ID.
  • Export before reset. Retained history is bounded daemon memory, not a durable audit store.
  • Do not overread sequence gaps. A subscriber may see gaps because its policy filters event types. Native collection sequence numbers are not the NFLOG sequence used to detect packet-log loss.
  • Do not invent rates. CPU usage is cumulative; memory and workspace bytes are samples. A rate requires elapsed time and counter deltas.
  • Keep findings separate. A grader’s score and diagnosis are environment logic, not proof supplied by the event collector.


What happens when collection fails?
The collector has a finite capacity (100,000 events by default). Observation errors such as a scan failure can stop the episode. Detected NFLOG sequence loss, socket overruns, or observation buffering failures also stop it instead of silently dropping evidence. This is not a promise that every possible loss is detectable.
Filesystem fingerprinting reads complete files only up to its 64 MiB limit; an oversized file causes an explicit failure. Reads and scans are not atomic. Monitoring avoids holding the action/reset lock while hashing and discards samples that cross a reset boundary.
Detailed enforcement-readiness and persisted failure-reason reporting remain follow-ups. The current health route is a minimal workload-liveness signal, not an attestation that every observation stream is complete.


What is deliberately absent from network observations?
These are packet-policy decisions with destination, protocol, and allow/deny outcome. There are no URLs, payloads, TLS contents, or PID attribution. An allowance does not prove a connection succeeded. Retransmissions may yield repeated events; established packets are not individually logged. Namespace-local loopback is not retained.


Build an investigation, not just a chart
In this example, the independent artifact check contradicts the harness’s success claim. The denied request is a possible lead, not an established cause. A useful next step is to inspect the allowed artifact and the task’s dependency assumptions, then rerun in a fresh controlled episode if needed. The runtime does not automatically join the events into a causal trace or determine whether the agent intended to cheat.

from openenv.core.openenvd import HarnessEventSink

The sink requires a runtime-supplied event descriptor. Publication grants no access to retained observations or grader secrets.
Harness benefit: harness authors can use shared lifecycle and access boundaries instead of recreating them for every experiment.
Integration scope
The model loop, task tools, and comparison runner. There is no automatic launcher for arbitrary external CLI harnesses. A remote model driver can keep its credentials outside the workload.

01 / Agent policy A
Work on the task
The agent edits its workspace with limited tools and explicit network permissions. Hidden tests and grader credentials stay outside its access.
Today: separate principals
The controller can use grader.read_file, grader.fs_diff, and grader.get_trajectory with a separate credential. Agent and grader permissions are declared ahead of time.
Calling the grader does not stop background agent processes, freeze the workspace, or replace its network policy. The surfaces coexist.
grader.run_oracle runs trusted operator code with daemon privileges. It is not an isolated verifier for executing submitted code. A daemon lock does not stop workload processes.
Harbor’s side of the contract
# Harbor task.toml — not openenvd config
[verifier]
environment_mode = "separate"

[verifier.environment]
docker_image = "your-org/verifier:version"
Harbor supports separate verification and declared artifact transfer. A dedicated verifier image contains its tests; tests/test.sh writes a numeric reward under /logs/verifier/.
Separate verifier · Verifier contract
What the integration must actually build
  • Block new actions and terminate all workload writers before collecting a submission.
  • Export selected artifacts safely; reject unsafe paths and preserve immutable evidence.
  • Start a provider-owned verifier sandbox with policy B before verifier code runs.
  • Keep secrets and reward outputs outside agent-writable locations. Executing submitted code needs isolation from grader secrets too.
  • Translate the verifier outcome into the environment’s reward contract.
There is an internal stop operation, but no public atomic “finish and seal” API. Reset restores the initial workspace—exporting after reset would lose the submission. Live network updates and hostname rules are not implemented.
The product can feel like “flip to verifier mode.” The implementation should hand off selected data to a separate execution identity, not elevate the running agent.

Step 01
A Linux runtime with the required capabilities
The daemon needs Linux root, network and mount namespace operations, veth/nftables support, writable cgroup v2 with cgroup.kill, and IPv4 forwarding already enabled. A provider must supply these capabilities inside an appropriate outer container or VM. An ordinary unprivileged container, macOS process, or default hosted Space is not sufficient.
The commands below assume a disposable Linux runtime, a root shell, and this PR checked out at /opt/OpenEnv. They install Python and system dependencies and prepare an empty workspace plus a protected demonstration asset.
# Inside a disposable, suitably isolated Linux runtime, as root.
# This example assumes the PR checkout lives at /opt/OpenEnv.
cd /opt/OpenEnv
apt-get update
apt-get install -y python3-venv iproute2 nftables conntrack \
  libseccomp2 libnetfilter-log1
python3 -m venv /opt/openenvd-venv
/opt/openenvd-venv/bin/pip install -e .

# Reserve UID/GID 65536 exclusively for this workload.
install -d -m 0755 -o root -g root /srv/echo-demo
install -d -m 0700 -o 65536 -g 65536 /srv/echo-demo/workspace
install -d -m 0700 -o root -g root /srv/echo-demo/assets
printf '%s\n' 'Echo preserves the input message.' \
  > /srv/echo-demo/assets/reference.txt
chmod 0600 /srv/echo-demo/assets/reference.txt
The provider enables forwarding before startup; this guide does not change host sysctls. The workspace’s parent remains root-owned and non-writable by the workload. The checkout and Python installation must be readable and traversable by UID 65536. This UID must not belong to another active workload.


Step 02
Append a policy to Echo’s existing manifest
Keep the current fields in envs/echo_env/openenv.yaml, including app: server.app:app. Add this top-level section. This is an append-only fragment, not a replacement manifest.
openenvd:
  enabled: true
  surfaces:
    agent:
      tools: [echo_message, echo_with_length]
    orchestrator:
      allow_lifecycle: true
    grader:
      tools: [grader.read_file]
      fs_read: ['/openenvd/assets/reference']
    observer:
      stream: [process, resource]
  privileged_assets:
    reference: reference.txt
Echo needs no outbound network access, so the omitted network section keeps default-deny egress. The grader can read one demonstration reference asset. The observer gets process and resource samples; vanilla Echo does not emit harness events.
Why no environment-class rewrite?
Echo’s server/app.py already calls create_app(EchoEnvironment, CallToolAction, CallToolObservation, ...). In this branch, that factory metadata lets openenvd discover the environment and action type. Custom apps without this metadata require an explicit --factory module:Class and, when needed, --action-class.
Although the original Echo server supports concurrent sessions, this daemon supervises one workload and one episode trajectory. Additional MCP sessions are transport handles, not additional independent environments.


Step 03
Launch openenvd in place of Echo’s Uvicorn command
The daemon binds to loopback at port 8100 and discovers Echo from its manifest. The reserved workload identity runs the environment; the root daemon owns the privileged surfaces and asset copies.
# Same root shell; distinct secrets, never shared with the agent.
export OPENENVD_ORCHESTRATOR_TOKEN="$(/opt/openenvd-venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OPENENVD_GRADER_TOKEN="$(/opt/openenvd-venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OPENENVD_OBSERVER_TOKEN="$(/opt/openenvd-venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"

/opt/openenvd-venv/bin/python -m openenv.core.openenvd \
  --manifest /opt/OpenEnv/envs/echo_env/openenv.yaml \
  --workspace /srv/echo-demo/workspace \
  --asset-root /srv/echo-demo/assets \
  --uid 65536 --gid 65536 \
  --host 127.0.0.1 --port 8100 --timeout 300
The process runs in the foreground. Client examples run in separate trusted processes on the same runtime, with the appropriate token supplied through deployment configuration. Tokens generated in this shell are not automatically available in a second shell. A delegated cgroup location can be selected with --cgroup-root.
What changes in an existing Echo image?
Replace its uvicorn server.app:app ... entrypoint with the command above using paths inside the image. Ensure its interpreter contains this PR’s OpenEnv code and the system packages. Update health checks to http://127.0.0.1:8100/health if the port stays 8100.
The existing manifest’s port: 8000 does not override the daemon’s CLI port. Its validation.resources section does not provision container limits or select the daemon timeout. The provider supplies outer resource limits; --timeout controls this runtime’s episode timeout.
The guide uses loopback deliberately. Remote exposure requires deployment-provided TLS and network access controls; the agent endpoint has no additional authentication.


Step 04
Connect each caller to its own surface
The agent sends MCP calls to /mcp. Infrastructure resets through authenticated /ws; the grader uses /mcp/grader; observers consume /observe. A legacy example that lets the same agent caller reset must be split across these roles.
Expected: the MCP result contains “Hello, isolation!”.
# Agent call: no lifecycle or grader credential.
curl --fail-with-body http://127.0.0.1:8100/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"echo_message","arguments":{"message":"Hello, isolation!"}}}'
Expected: reset returns an observation. This starts a new episode and restores the managed workspace.
# Trusted orchestration process, with the orchestrator token.
import asyncio
import os
from openenv.core.generic_client import GenericEnvClient

async def main():
    async with GenericEnvClient(
        base_url="http://127.0.0.1:8100",
        headers={"Authorization":
            f"Bearer {os.environ['OPENENVD_ORCHESTRATOR_TOKEN']}"},
    ) as env:
        result = await env.reset(seed=0)
        print(result)

asyncio.run(main())
Expected: the response includes “Echo preserves the input message.” This demonstrates protected access, not a new reward function.
# Trusted grader process, with only the grader token.
import asyncio
import os
from openenv.core.openenvd import GraderClient

async def main():
    async with GraderClient(
        "http://127.0.0.1:8100/mcp/grader",
        os.environ["OPENENVD_GRADER_TOKEN"],
    ) as grader:
        print(await grader.call_tool(
            "grader.read_file",
            {"path": "/openenvd/assets/reference"},
        ))

asyncio.run(main())
Expected: configured process/resource events arrive while the workload runs. Their sequence numbers restart on reset.
# Trusted observer process, with only the observer token.
import asyncio
import os
from openenv.core.openenvd import observer_stream

async def main():
    async for event in observer_stream(
        "ws://127.0.0.1:8100/observe",
        os.environ["OPENENVD_OBSERVER_TOKEN"],
    ):
        print(event["type"], event["data"])

asyncio.run(main())

What Echo does—and does not—demonstrate
Echo tests tool access and principal separation. It does not write task files, call external services, publish harness events, or run a Harbor verifier. Those features need an environment or harness that exercises them. A workspace restore check requires an intentionally mutable fixture. Network enforcement needs a controlled network probe; the two Echo tools do not issue one.
Disabling or removing the policy returns the CLI to the original app, but that also removes the new runtime’s boundaries. It is a compatibility path, not an equivalent deployment mode.
Sources: Echo manifest · Echo app factory · Daemon startup
Execution with explicit boundaries.
The current implementation separates agent tools, episode lifecycle, privileged grading, and observation. The Harbor handoff extends this model through a proposed submission-and-verification integration.
