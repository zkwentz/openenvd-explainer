One hook into the harness

Inside the workload, publish adapter events through the daemon-provided write-only pipe.

from openenv.core.harness import MCPHarnessAdapter
from openenv.core.openenvd import HarnessEventSink

adapter = MCPHarnessAdapter(
    event_sink=HarnessEventSink()
)

The sink requires a runtime-supplied event descriptor. Publication grants no access to retained observations or grader secrets.

Harness benefit: harness authors can use shared lifecycle and access boundaries instead of recreating them for every experiment.
Integration scope

The model loop, task tools, and comparison runner. There is no automatic launcher for arbitrary external CLI harnesses. A remote model driver can keep its credentials outside the workload.

Reset covers the managed workspace, not every writable path or external service. This is not bit-for-bit replay.

Configurable signals

# Fragment for openenv.yaml
openenvd:
  enabled: true
  surfaces:
    observer:
      stream:
        - harness_events
        - fs_diff
        - process
        - network
        - resource

An authenticated observer_stream() consumer can power a live view or attach evidence to failed evaluations.

Integration scope

Durable storage and dashboards are separate integrations. External run and episode identifiers preserve context because event sequence numbers restart on reset.

Different signals, different claims. Harness events are reports. Filesystem and process samples can miss brief activity. Network events are firewall decisions, not proof of successful connections.

Events live in bounded daemon memory. Scans are not atomic. This is useful diagnostic evidence, not a complete audit trail.

01 / Agent policy A

Work on the task

The agent edits its workspace with limited tools and explicit network permissions. Hidden tests and grader credentials stay outside its access.

Today: separate principals

The controller can use grader.read_file, grader.fs_diff, and grader.get_trajectory with a separate credential. Agent and grader permissions are declared ahead of time.

Calling the grader does not stop background agent processes, freeze the workspace, or replace its network policy. The surfaces coexist.

grader.run_oracle runs trusted operator code with daemon privileges. It is not an isolated verifier for executing submitted code. A daemon lock does not stop workload processes.

Harbor’s side of the contract

# Harbor task.toml — not openenvd config
[verifier]
environment_mode = "separate"

[verifier.environment]
docker_image = "your-org/verifier:version"

Harbor supports separate verification and declared artifact transfer. A dedicated verifier image contains its tests; tests/test.sh writes a numeric reward under /logs/verifier/.

Separate verifier · Verifier contract

What the integration must actually build
  • Block new actions and terminate all workload writers before collecting a submission.
  • Export selected artifacts safely; reject unsafe paths and preserve immutable evidence.
  • Start a provider-owned verifier sandbox with policy B before verifier code runs.
  • Keep secrets and reward outputs outside agent-writable locations. Executing submitted code needs isolation from grader secrets too.
  • Translate the verifier outcome into the environment’s reward contract.

There is an internal stop operation, but no public atomic “finish and seal” API. Reset restores the initial workspace—exporting after reset would lose the submission. Live network updates and hostname rules are not implemented.

The product can feel like “flip to verifier mode.” The implementation should hand off selected data to a separate execution identity, not elevate the running agent.

Instance A / Offline
No egress

No destination allowances. A model driver requiring an external inference API runs outside the offline workload.

Instance B / Connected
One allowance

An explicit IPv4 CIDR, TCP or UDP, and destination ports. Same task and fresh workspace.

Compare behavior, not just scores

Network observations help distinguish local problem-solving, remote dependencies, and failures caused by blocked requests.

A denied packet shows a blocked attempt. It does not establish malicious intent, and an allowed packet does not prove a successful connection.
Experiment orchestration

The comparison uses separately configured instances; live policy switching within an episode is not implemented. Protected destinations stay blocked, even under broad allowances. IPv6 cannot leave the workload.

DNS needs its own allowances. An allowed proxy can relay traffic onward. Destination rules do not inspect payloads or stop an allowed service from revealing answers.

Execution with explicit boundaries.

The current implementation separates agent tools, episode lifecycle, privileged grading, and observation. The Harbor handoff extends this model through a proposed submission-and-verification integration.

Scope & sources

Source-checked design examples, not executed end-to-end demos. Linux root, namespace/firewall capabilities, cgroup v2, system packages, and protected asset paths are required.
